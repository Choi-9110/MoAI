# 자격 판정 설계 — 2단계 필터링

> 대상 확장: 지원사업 + **예비창업자** + **대출·정책자금**
> 결론: 하드 필터(코드) → 소프트 판정(LLM + 사용자 확인) 2단계로 간다.

---

## 0. 질문에 대한 답

> "기본조건은 맞춰서 필터링하는데, 그 이상 딥한 조건들은 내용 파악하고 정해야 하는 거 아니냐?"

**맞습니다.** 그리고 이게 이 제품의 핵심 난관입니다.

다만 한 가지 더 짚을 게 있습니다 — **모든 조건을 컬럼으로 만들려는 시도는 반드시 실패합니다.**
공고의 자격 조건은 종류가 사실상 무한하기 때문입니다.

```
"최근 3년 이내 동일 사업 수혜 이력이 없을 것"
"대표자가 만 39세 이하일 것"
"창업진흥원 주관 창업교육 20시간 이상 이수자"
"신청일 기준 국세·지방세 체납이 없을 것"
"「중소기업기본법」 제2조에 따른 중소기업"
```

이걸 전부 컬럼으로 만들면 테이블이 200개 컬럼이 되고, 새 공고가 뜰 때마다 스키마를 바꿔야 합니다.

**해법은 조건을 두 종류로 나누는 것입니다.**

---

## 1. 2단계 구조

```
┌─ 1단계 · 하드 필터 ────────────────────────────┐
│ 구조화된 소수의 조건. DB 쿼리로 계산.            │
│ 업력 · 지역 · 업종 · 매출 · 인원 · 법인 · 신용    │
│ → 명확히 배제되는 것만 걸러낸다 (ineligible)     │
└────────────────────┬───────────────────────────┘
                     ↓ 통과한 공고만
┌─ 2단계 · 소프트 판정 ──────────────────────────┐
│ 비정형 조건. LLM 이 공고 원문에서 추출.          │
│ → 자동 판정하지 않고 사용자에게 체크리스트로 제시 │
│ → "이 조건에 해당하시나요?" (예 / 아니오 / 모름)  │
└────────────────────────────────────────────────┘
```

**핵심 원칙: 2단계는 자동 판정하지 않는다.**
"최근 3년 내 수혜 이력" 같은 건 시스템이 알 수 없습니다.
모르는 걸 아는 척하면 "지원 가능"이라 해놓고 실제로는 자격 미달인 사고가 납니다.
사용자에게 묻고, 답을 저장해서 **다음 공고부터는 자동 적용**합니다.

이러면 쓸수록 정확해집니다. (= "입력해두면 알아서" 원칙)

## 2. 지금 모델의 한계 3가지

### ① `CompanyProfile` 이 "사업자 있는 기업"을 전제한다

| 필드 | 예비창업자의 경우 |
|---|---|
| `businessNumber` | 없음 |
| `foundedAt` | 없음 → 업력 계산 불가 |
| `annualRevenue` | 없음 |
| `isCorporation` | 해당 없음 |

현재 로직대로면 예비창업자는 대부분의 공고가 `조건부`로 빠집니다.
**예비창업자 전용 공고가 오히려 안 걸러지는 역설**이 생깁니다.

→ `stage` 필드로 갈래를 나누고, 예비창업자용 필드를 별도로 둡니다.

### ② `Grant.category` 에 대출·융자가 없다

대출은 성격이 완전히 다릅니다.

| | 지원사업 | 대출·정책자금 |
|---|---|---|
| 성격 | 무상 지원 | 상환 의무 |
| 판정 기준 | 자격 요건 | **신용등급·부채비율·담보** |
| 핵심 정보 | 지원 금액 | **금리·한도·상환기간·보증기관** |
| 주기 | 공고 → 마감 | **상시 또는 매월** |

### ③ 캘린더가 "마감일 있는 공고"만 전제한다

대출은 연중 상시이거나 매월 반복입니다. 마감일 축에 배치할 수 없습니다.

→ `recurrence` 로 구분하고, 상시 항목은 캘린더가 아닌 **별도 섹션**에 노출합니다.

## 3. 제안 스키마

### CompanyProfile 확장

```ts
// 신규
stage: 'preliminary' | 'registered'   // 예비창업자 / 사업자 등록됨

// 예비창업자용
founderAge: number | null             // 청년창업 요건
founderGender: 'M' | 'F' | null       // 여성기업 요건
completedPrograms: string[]           // 이수한 창업교육
priorStartupCount: number | null      // 재창업 여부

// 대출용
creditGrade: string | null            // 신용등급 (NICE/KCB)
hasTaxArrears: boolean | null         // 체납 여부
debtRatio: number | null              // 부채비율

// 2단계 답변 저장소 — 한 번 답하면 재사용
conditionAnswers: Record<string, 'yes' | 'no' | 'unknown'>
```

### Grant 확장

```ts
category: … | 'loan'                  // 대출 추가

// 신청 가능 대상
applicantTypes: ('preliminary' | 'individual' | 'corporate')[]

// 접수 주기
recurrence: 'once' | 'monthly' | 'always'

// 대출 전용 (category === 'loan' 일 때만)
loanTerms: {
  interestRateMin: number | null      // 연 %
  interestRateMax: number | null
  limitAmount: number | null          // 한도
  termMonths: number | null           // 상환기간
  graceMonths: number | null          // 거치기간
  guarantor: string | null            // 신보 / 기보 / 지역신보
  minCreditGrade: string | null
} | null

// ★ 2단계 소프트 조건 — LLM 이 원문에서 추출
additionalConditions: {
  id: string                          // 안정적 키 (답변 재사용용)
  text: string                        // "최근 3년 내 동일 사업 수혜 이력이 없을 것"
  type: 'exclusion' | 'requirement' | 'preference'
  autoField: string | null            // 프로필로 자동 판정 가능하면 필드명
  sourceQuote: string                 // 공고 원문 인용 (검증용)
}[]
```

`sourceQuote` 가 중요합니다. LLM 추출은 틀릴 수 있으므로 **원문 근거를 항상 함께 저장**해
사용자가 직접 확인할 수 있게 합니다.

## 4. 추출 파이프라인

```
공공 API 수집
    ↓
공고 원문 + 첨부(PDF/HWP) 텍스트 추출
    ↓
LLM 구조화 (2패스)
  1패스: 하드 조건 → 컬럼으로 (업력/지역/업종/금액/대출조건)
  2패스: 나머지 조건 → additionalConditions 배열로 + 원문 인용
    ↓
검증: 필수 필드 누락 / 값 범위 이상 → 사람 검토 큐로
    ↓
DB 적재
```

**하드 조건 추출은 보수적으로.** 확신 없으면 `null` 로 두는 게 낫습니다.
`null` 이면 "조건부"로 표시되어 사용자가 확인하지만,
잘못된 값이 들어가면 **지원 가능한 공고를 놓치거나 자격 없는 공고를 추천**하게 됩니다.

## 5. 화면에 미치는 영향

### 캘린더
- 마감일 있는 공고 → 기존 그리드
- 상시·매월 대출 → 캘린더 하단 **"상시 모집" 섹션**으로 분리

### 공고 상세
```
지원 자격 검토 (3/4 충족)
  ✓ 업력   창업 3년 이내 — 현재 2년
  ✓ 지역   서울 소재 — 충족
  ✕ 인증   벤처기업확인 미보유
  ? 매출액 정보 없음

추가 확인이 필요해요            ← 2단계
  □ 최근 3년 내 동일 사업 수혜 이력이 없나요?
      "…최근 3년 이내 수혜 기업은 제외" (공고 원문)
  □ 대표자가 만 39세 이하인가요?
                      [예] [아니오] [모르겠어요]
```

한 번 답하면 `conditionAnswers` 에 저장되어 **다음 공고부터 자동 반영**됩니다.

## 6. 착수 순서 제안

| 순서 | 작업 | 이유 |
|---|---|---|
| 1 | `stage` + 예비창업자 필드 추가 | 대상이 2배로 늘어남 |
| 2 | `applicantTypes` · `recurrence` 추가 | 대출·상시 수용 |
| 3 | `loanTerms` + `loan` 카테고리 | 대출 도메인 |
| 4 | `additionalConditions` + 체크리스트 UI | **2단계 판정의 핵심** |
| 5 | 공공 API 수집기 | 실데이터 |
| 6 | LLM 2패스 추출 | 자동화 |

4번까지 하면 데이터만 들어오면 되는 상태가 됩니다.
5·6번은 데이터 소스별로 하나씩 붙이면 됩니다.
