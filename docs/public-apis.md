# 공공 API 조사 결과

> 조사일: 2026-08-20
> 대상: 지원사업 공고를 긁어올 수 있는 공공 오픈API

---

## 결론

| 소스 | 지원사업 공고 API | 판정 |
|---|---|---|
| **기업마당** (중기부) | ✅ 있음 | **1순위** — 범위가 가장 넓음 |
| **K-Startup** (창업진흥원) | ✅ 있음 | **2순위** — 창업 분야 전문 |
| **소상공인24** | ❌ **없음** | 공고 API 미개방 (상권정보만 있음) |

**소상공인24는 지원사업 공고 오픈API가 없습니다.**
다만 소상공인 지원사업 상당수가 기업마당에 함께 올라오므로, 기업마당으로 대체 가능합니다.

---

## 1. 기업마당 (Bizinfo) — 1순위

중소벤처기업부가 운영하는 **지원사업 통합 포털**. 부처·지자체·공공기관 공고가 모입니다.

```
GET https://www.bizinfo.go.kr/uss/rss/bizinfoApi.do
```

| 항목 | 내용 |
|---|---|
| 인증 | `crtfcKey` (기업마당에서 직접 발급 — 공공데이터포털 아님) |
| 형식 | JSON / XML(RSS) |
| 문의 | 02-867-9765 |

### 요청 파라미터

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `crtfcKey` | ✅ | 인증키 |
| `dataType` | | `json` 또는 `rss` |
| `searchCnt` | | 조회 건수 (비우면 전체) |
| `searchLclasId` | | 분야 코드 `01`~`09` |
| `hashtags` | | 해시태그 다중 지정 |
| `pageUnit` / `pageIndex` | | 페이징 |

### 분야 분류

금융 · 기술 · 인력 · 수출 · 내수 · 창업 · 경영 · 기타

> **대출·정책자금은 "금융" 분야에 들어옵니다.**
> 앞서 논의한 `category: 'loan'` 수집 경로가 여기서 열립니다.

---

## 2. K-Startup (창업진흥원) — 2순위

창업 분야 공고 전문. 공공데이터포털 경유입니다.

```
https://www.data.go.kr/data/15125364/openapi.do
데이터셋: 창업진흥원_K-Startup(사업소개,사업공고,콘텐츠 등)_조회서비스
```

| 항목 | 내용 |
|---|---|
| 비용 | 무료 |
| 심의 | **자동승인** |
| 트래픽 | 개발계정 일 10,000건 (운영계정 전환 시 증가) |
| 형식 | REST, JSON + XML |
| 인증 | 공공데이터포털 서비스키 |

### 제공 엔드포인트 (4종)

- 지원사업 공고 정보
- 통합공고 지원사업 정보
- 창업 콘텐츠 정보
- 창업 통계보고서 정보

### 제공 항목

사업명 · 사업유형 · 사업개요 · **지원대상** · **모집기간** · 신청방법 · 문의처

> 상세 요청/응답 명세는 활용신청 후 내려받는 가이드 문서(zip)에 있습니다.
> Swagger UI: `nidview.k-startup.go.kr`

## 3. 소상공인24 — 공고 API 없음

확인 결과 **지원사업 공고 오픈API는 개방되어 있지 않습니다.**

공개된 것은 상권 데이터뿐입니다.

```
소상공인시장진흥공단_상가(상권)정보_API
https://www.data.go.kr/data/15012005/openapi.do
→ 상호명·업종코드·주소·좌표. 우리 용도와 무관.
```

### 대안

1. **기업마당으로 커버** — 소상공인 지원사업 다수가 기업마당에 게시됨
2. **중소벤처24** (`smes.go.kr/main/dbCnrs`) — Open API 제공 여부 추가 확인 필요
3. 최후 수단: `sbiz.or.kr` 공고 게시판 크롤링 (이용약관 확인 필요)

## ⚠️ 진짜 문제 — 수집한 데이터를 그대로 쓸 수 없다

API가 내려주는 자격 요건은 **자유 텍스트**입니다.

```json
{
  "사업명": "2026년 초기창업패키지",
  "지원대상": "창업 3년 이내 중소기업으로서 서울시에 사업장을 둔 자",
  "신청기간": "2026-08-01 ~ 2026-09-15"
}
```

우리 하드 필터는 이런 컬럼을 요구합니다.

```ts
maxBusinessYears: 3
targetRegions: ['서울']
applicantTypes: ['individual', 'corporate']
```

**이 변환이 없으면 캘린더 판정이 전부 "정보 부족"으로 나옵니다.**

### 수집 파이프라인 (2패스)

```
① 원문 수집      API → grants 테이블에 raw_metadata 로 통째 저장
                 (title, agency, 신청기간만 먼저 구조화)
        ↓
② 하드 조건 추출  LLM 이 지원대상 문장 → 컬럼으로 변환
                 확신 없으면 null (틀린 값보다 낫다)
        ↓
③ 소프트 조건 추출 나머지 조건 → additionalConditions 배열 + 원문 인용
        ↓
④ 검증           필수 필드 누락 / 값 이상 → 사람 검토 큐
```

②를 건너뛰고 ③만 하면 매번 LLM 을 태워야 해서 비용이 감당되지 않습니다.
**한 번 구조화해두고 캐시**하는 것이 지금 만든 `eligibility_checks` 구조의 전제입니다.

## 착수 순서

| 순서 | 작업 | 담당 |
|---|---|---|
| 1 | 기업마당 인증키 발급 신청 | 👤 사용자 |
| 2 | 공공데이터포털 가입 + K-Startup 활용신청 (자동승인) | 👤 사용자 |
| 3 | 수집기 골격 (`GrantCollector` 인터페이스 + 소스별 어댑터) | 개발 |
| 4 | 원문 → `grants` 적재 (raw_metadata 보존) | 개발 |
| 5 | LLM 하드 조건 추출 (Gemma 또는 API) | 개발 |
| 6 | 중복 제거 (같은 공고가 여러 소스에 뜸) | 개발 |
| 7 | 일일 수집 스케줄러 | 개발 |

**1·2번은 사용자만 할 수 있습니다.** 키가 나오면 3번부터 바로 붙입니다.

키 없이도 3~4번 골격은 미리 만들 수 있으므로, 발급 기다리는 동안 진행 가능합니다.
