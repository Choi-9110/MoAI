# 요약 한 장 — 레퍼런스

여기 있는 이미지는 **참고 자료가 아니라 사양**이다.

"한 장으로 압축한다"가 실제로 어떤 모양인지는 말로 옮기기 어렵다.
레퍼런스에서 뽑아낸 규칙이 `packages/shared/src/poster.ts` 의 블록 타입과
`poster-revise.ts` 의 프롬프트가 됐다.

**이미지 자체는 모델에 넘길 수 없다. 그래서 이 문서가 이미지를 대신해
프롬프트로 들어간다.** 레퍼런스를 추가하면 이 문서도 반드시 같이 갱신할 것.

파일명도 그 축으로 붙였다.

## 골격 — 6장이 모두 지키는 순서

```
1  제목 배너        기업 현황 · {구성 유형} (괄호 안에 사업·공고명)
2  기관 카드 2×2    역할 배지 + 기관명 + 보조정보 / 항목별 아이콘 불릿 3줄
3  사업 목표        세로라벨 + 본문 한 덩어리 + 메타 칩 줄
4  내부 문제점      세로라벨 + 번호 카드 3개
5  해결 방안        세로라벨 + 번호 카드 3개   ← 4번과 번호로 1:1 대응
6  외부 문제점      세로라벨 + 한 줄 박스 (빨강)
7  해결 방안        세로라벨 + 한 줄 박스 (파랑·점선)
8  기대 효과        세로라벨 + 지표 5~6칸
```

이 순서는 우연이 아니다. **문제 → 해결 → 근거**를 두 번(내부·외부) 반복하고
숫자로 닫는다. 심사자가 읽는 순서라서 바꾸면 안 된다.

## 규칙

### 세로 라벨이 카테고리다
왼쪽 좁은 칸에 "내부 문제점", "해결 방안", "기대 효과"가 세로로 붙는다.
이게 문서의 뼈대라서 사용자가 고칠 수 없다. 고치는 건 오른쪽 내용뿐이다.
→ `PosterBlock.category`, 편집 단위는 `collectSlots()` 가 뽑는 칸

### 라벨은 낱말 단위로 끊는다
"내부 문제점"은 `내부` / `문제점` 두 줄이다. `내부문제` / `점` 이 아니다.
→ `splitCategoryLabel()`

### 내부 문제점과 해결 방안은 번호로 1:1 대응한다
6장 전부 예외가 없다. 문제 2번을 고치면 **해결 2번이 반드시 따라 움직인다.**
개수도 같아야 한다(대부분 3개).
→ `POSTER_SYSTEM_PROMPT` 의 연쇄 수정 규칙

### 외부 문제점 / 해결 방안은 상하로 쌓는다
01번만 좌우 대비였고 나머지 5장은 전부 위아래다. 외부 요인은 문장이 길어서
좌우로 쪼개면 읽기 어렵다. **상하 스택이 기본**이다.

### 사업 목표 아래에 메타 칩 줄이 붙는다
6장 중 4장에 있다. 과제번호 · 수행기간 · 총 사업비(정부지원 비율) · TRL ·
목표 산출물이 작은 칩으로 한 줄에 놓인다.

```
중소기업기술정보진흥원 · 2024 창업성장기술개발(디딤돌)  │  2024.05 ~ 2025.04 (12개월)
총 1.60억원 (정부 1.2억 · 74.8%)  │  주관 90% + 외주 10%  │  특허 1건 · 상표/디자인 2건 목표
```

사업계획서 표지에 들어가는 값과 같다. 요약에서 이게 빠지면 심사자가
"이 과제가 뭔지" 알 수 없다.

### 본문 안에서 핵심을 굵게 만든다
수치와 기술명은 문장 안에서 굵다 — "일 36kW 입력으로 **48kW 생산(에너지 효율
33%↑)**". 통문장을 다 읽지 않아도 숫자가 먼저 눈에 들어와야 한다.

### 기대 효과는 값 + 방향 + 근거 3층이다
```
   ✓
연비            ← 지표 이름
15% ↑           ← 값 + 방향 화살표
4.5~5.17km/L    ← 근거 (2줄까지)
(5톤 기준)
```
화살표는 좋아지는 방향을 뜻한다. `NOx 68% 개선`, `관제 부담 50~80%↓` 처럼
줄어드는 게 좋은 지표도 있어서 값만으로는 판단이 안 된다.

### 색은 의미를 나른다
문제는 빨강, 해결은 파랑/강조, 기대 효과는 초록, 라벨 바탕은 짙은 남색.
브랜드킷 채택 후 딥그린 / 잉크 / 빨강 / 주황 네 가지로 옮겼다.
한 장에 색이 흩어지면 무엇이 중요한지 사라진다.
→ `POSTER_TONES`

### 카드는 3개, 설명은 2~3줄
한 줄 28자를 넘지 않는다. 넘치면 자르지 말고 다시 요약한다 — 압축이 곧 검토다.
→ `POSTER_LIMITS`, `findOverflows()`

### 숫자만 있고 근거가 없으면 빈틈이다
원본에는 없는 개념이다. 레퍼런스는 이미 완성된 문서라 모든 칸이 차 있지만,
우리는 **작성 중인 문서**를 다룬다. 지어내지 않으려면 빈 곳을 빈 곳으로
표시해야 한다.
→ `Gap`, `openGaps()`

### 모든 칸이 서로 맞물린다
문제를 고치면 그 문제를 겨냥하던 해결 방안이 바뀌고, 기대 효과의 수치 근거도
흔들린다. 그래서 재작성은 칸 단위 패치가 아니라 문서 전체 재구성이고,
무엇이 따라 바뀌었는지 사용자에게 보여준다.
→ `POSTER_SYSTEM_PROMPT`, `diffPoster()`

## 역할(role) 목록

레퍼런스에 실제로 나온 것 전부. 구성 유형에 따라 크게 달라진다.

| 유형 | 나온 역할 |
|---|---|
| 컨소시엄 | 주관 · 참여 · 공동 · 위탁용역 · 수요 · 수요처 · 자문 |
| 단독 수행 | 주관 · 연구팀 · 외주·시험 · 선행연구·IP |
| 기업주도형 | 주관 · 평가기관 · 보유 기술·IP · 성장·판로 · 글로벌 판로 |

단독 수행에서는 "기관"이 아니라 **역량 구획**이 카드가 된다. 협력사가 없어도
같은 레이아웃이 성립하도록 만든 장치다.

## 아직 구현 안 된 것

레퍼런스에는 있는데 코드에 없다. 사업계획서 작업 때 같이 반영할 것.

- **메타 칩 줄** — 과제번호·기간·사업비·TRL. 블록 타입이 없다
- **역할 목록 확장** — `ORG_ROLES` 가 5개뿐이다 (위 표는 15개 이상)
- **본문 인라인 강조** — 지금은 통문장 평문이다
- **지표 방향 화살표** — `MetricsBlock.items` 에 방향 필드가 없다
- **기관 카드 항목별 아이콘** — 지금은 그냥 텍스트 줄이다
- **기관 그룹 묶음** — 03번처럼 "설계·해석·실증 5개 기관" 안에 여럿
- **외부 문제↔해결 상하 스택** — 지금 `compare` 는 좌우다
