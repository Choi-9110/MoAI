# 증빙 — 수집한 공고 데이터

MoAI(모아이)가 실제로 무엇을 얼마나 모아 두었는지 보이는 자료다.
"3만 건을 수집했다"는 문장 하나로는 아무것도 증명되지 않는다.

## 무엇부터 열면 되나

| 열어 볼 사람 | 파일 |
|---|---|
| **심사자 · 처음 보는 사람** | `csv/summary.csv` → `csv/grants-active.csv` |
| 데이터를 직접 뜯어볼 사람 | `csv/grants.csv` |
| 개발자 · 연동하는 쪽 | `grants.schema.json`, `dataset/*.json` |

## 파일

| 경로 | 내용 |
|---|---|
| `csv/summary.csv` | 요약표 54줄 — 총계·유형별·기관별 분포 + **필드별 채움률** |
| `csv/grants-active.csv` | 접수 진행 중 278건. 마감 임박순 |
| `csv/grants.csv` | 전체 29,834건 (27MB). 접수 중인 것이 위, 그 다음 마감 임박순 |
| `dataset/grants_001~030.json` | 원본. 파일당 1,000건 |
| `grants.sample.json` | 원본에서 뽑은 표본 — 구조만 보고 싶을 때 |
| `grants.schema.json` | 필드 정의 |
| `stats.json` | 집계 수치 (원본 형식) |

CSV 는 `dataset/*.json` 에서 만든다. 원본이 갱신되면 다시 돌린다.

```bash
node scripts/evidence-to-csv.mjs
```

## CSV 를 따로 내는 이유

JSON 은 프로그램이 읽기에 좋지만 **사람이 열어 볼 수 없다.** 3만 건이 든
파일 서른 개를 받아서 무엇을 확인하겠는가. 그래서 엑셀에서 바로 열리는
표로 다시 낸다. 원본은 그대로 두고 사본을 만드는 것이므로, 둘이 어긋날
일은 없다.

옮기면서 세 가지를 손봤다.

1. **시각을 한국시간으로 바꿨다.** 원본은 UTC 라
   `2026-11-30T14:59:59Z` 인데, 이걸 그대로 적으면 마감이 11월 30일인지
   12월 1일인지 사람이 알 수 없다.
2. **코드값에 한글을 붙였다.** `space`, `preliminary` 를 보고 입주공간·
   예비창업자를 떠올릴 사람은 만든 사람뿐이다. 원래 코드도 괄호로 함께
   남겨 스키마와 대조할 수 있게 했다.
3. **BOM 을 붙였다.** 없으면 엑셀에서 한글이 깨진다.

컬럼은 우리가 해석한 값 뒤에 **기관이 실제로 써 놓은 원문**(`raw.*`)이
따라온다. 해석이 맞는지 직접 대조할 수 있어야 하기 때문이다.

## 빈 칸에 대해

`summary.csv` 아래쪽 「필드 채움률」을 보면 비어 있는 컬럼이 있다.

| 필드 | 채움률 | 왜 |
|---|---|---|
| 대상업종 · 지원금 상·하한 · 종업원수 상한 · 연매출 상한 · 요구인증 · 법인한정 | 0% | K-Startup 공개 API 가 이 값을 주지 않는다 |
| 지원자격 원문 · 제외대상 원문 | 0.9% / 0.4% | 공고 상세에만 있고 목록 API 에는 거의 없다 |
| 대상지역 | 45.4% | 원문에 "전국"만 적힌 공고가 많다 (`raw.rawRegion` 으로 확인 가능) |

**숨기지 않고 먼저 밝힌다.** 지원 자격 판정은 채워진 필드(업력·지역·
지원대상·연령)로만 하고, 값이 없는 항목은 "지원 가능"으로 단정하지 않고
**조건부**로 표시한다. 없는 데이터로 판정한 척하는 것이 훨씬 나쁘다.

비어 있는 필드는 공고 상세 페이지를 따로 수집해 채워 나간다.
