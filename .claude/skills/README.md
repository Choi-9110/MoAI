# 이 폴더의 스킬

**이 저장소에서만** 쓴다. 사용자 전역(`~/.claude/skills/`)이 아니라 저장소 안에
두었으므로 **다른 프로젝트에서는 보이지 않는다.** 다른 폴더에서 CLI 를 띄워
확인했다 — 스킬 목록에 안 나온다.

| 스킬 | 쓰는 곳 |
|---|---|
| `gov-bizplan` | 사업계획서 절 집필 (`apps/agent` → Claude CLI) |

## 어떻게 불려 오는가

**CLI 의 스킬 기능을 켜지 않는다.** 대신 폴더를 읽을 수 있게 열어 두고,
요청문에 `SKILL.md` 경로를 한 줄 알려 준다. 모델이 필요하다고 판단하면
그때 Read 로 연다.

스킬 기능을 켜지 않는 이유는 값 때문이다. 켜면 우리 스킬 하나 때문에
클로드 코드 **기본 스킬 12종의 목록까지 통째로** 시스템 프롬프트에 실린다.
우리 스킬은 실행 파일 없는 문서라 Read 로 열어도 결과가 같다.

### 실측 (하이쿠, 빈 요청 1회 · 시스템 프롬프트 크기)

| 구성 | 토큰 | 스킬 목록 |
|---|---|---|
| 아무것도 지정 안 함 (예전 방식) | 21,513 | 기본 12 + 우리 1 + **사용자 개인 스킬** |
| `--setting-sources project` | 20,460 | 기본 12 + 우리 1 |
| `--safe-mode` | 17,164 | 기본 12 |
| `--safe-mode --disable-slash-commands` | **15,192** | 없음 ← 지금 방식 |

예전에는 아무것도 지정하지 않아 `ir-search`, `discord:access` 같은 **이 프로젝트와
무관한 개인 스킬까지** 매 호출에 딸려 왔다. 공고 판정은 공고 수만큼 도는
작업이라 이 차이가 그대로 누적된다.

### 작업별

| 작업 | 스킬 폴더 |
|---|---|
| 사업계획서 절 집필 | 열어 둠 (`--add-dir`) + 요청문에 경로 안내 |
| 공고 판정 · 요약 한 장 | 안 열음 |

두 경우 모두 `--safe-mode --disable-slash-commands` 다. 이 조합에서도
`--add-dir` 파일 읽기는 그대로 된다 (확인함).

## 워크플로우가 어긋나는 문제

`gov-bizplan` 은 공고 분석 → RFP 분석 → 리서치 4종 → 8항목 집필 → 검증까지
**전체 흐름**을 갖고 있다. 우리는 이미 목차를 정해 두고 절 단위로 부르므로,
그냥 알려 주기만 하면 모델이 스킬의 순서로 갈아타 "먼저 공고를
분석하겠습니다" 하고 엉뚱한 것을 내놓는다.

그래서 경로와 함께 **쓸 범위를 좁혀서** 준다 — 문장 규칙·정량화·평가위원
관점 점검에만 쓰고, 목차와 진행 순서는 우리 것을 따르라고.
(`apps/agent/src/plan/plan.service.ts` 의 `skillNote`)

## 끄려면

`apps/agent/.env` 에 `PLAN_USE_SKILLS=false`.
폴더 위치를 옮겼으면 `SKILLS_DIR` 로 지정한다 (기본값은 위로 올라가며 찾는다).

## 스킬을 더 넣을 때

`.claude/skills/<이름>/SKILL.md` 로 두고, `skillNote` 에 경로를 알려 준다.
**알려 주는 순간부터 그 한 줄만큼 값이 붙는다** — 본문은 열 때만 붙는다.
