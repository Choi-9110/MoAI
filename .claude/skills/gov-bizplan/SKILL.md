# gov-bizplan — 정부사업 사업계획서 작성 스킬

공고문 하나로 시작해 제출 가능한 계획서 초안까지 가는 워크플로우. AI는 문장 요약 도구가 아니라 **논리를 조립하는 리서치 파트너**로 쓴다.

## 절대 원칙 (모든 단계 공통)

1. **리서치 우선주의** — 본문은 언제든 금방 쓴다. 시간은 리서치(논문·특허·경쟁제품·연구동향)에 최대로 배분하고, 리서치 산출물을 보관했다가 본문의 근거로 인용한다.
2. **맥락 누적 참조** — n번 항목 작성 시 리서치 4종 + 1~(n-1)번 산출물을 전부 참조한다. 앞 산출물과 모순되는 내용 금지.
3. **증명형 문장** — 모든 주장·수치에 근거·출처. 산식(대상 수 × 빈도 × 손실), M+N 시점, 기간+개수 정량화. 출처 없는 "엄청난·획기적" 금지. 어미는 개조식(~함/~됨/~임/~음).
4. **인간 게이트 2곳** — ⓐ공고 분석 후 지원 여부·대상 RFP를 사용자가 확정(RFP가 복수면 반드시 질문, 임의 선택 금지) ⓑAI 초안은 제출본이 아님: 팩트체크·비판적 검토를 사용자에게 요청.
5. **교차 검증 내장** — 집필에 쓰지 않은 별도 컨텍스트(서브에이전트)로 전체 정합성·평가위원 관점 검토.
6. **할루시네이션 3중 방어** — 모르면 모른다고 표기("확인 필요") / 부족한 정보는 사용자에게 질문 / 모든 수치에 출처.

## 프롬프트 6요소 공식

모든 작업 지시는 [역할 + 맥락 + 동작]을 기본으로, 문서 산출 시 [형식 + 예제]를 추가한다 (어조는 선택).
복합 요구는 나눠 보내지 말고 한 번에 조합한다. 수정 루프: "다시"(재학습·구체화) / "방향 전환" / "평가위원 검증" — [references/prompts.md](references/prompts.md) 보조 프롬프트 참조.

## 워크플로우

작업 시작 시 과제 폴더를 만들고(사용자 지정 위치, 예: `<과제명>/산출물/`) 각 단계 결과를 아래 파일명으로 저장한다.

| 단계 | 할 일 | 산출물 | 프롬프트 |
|---|---|---|---|
| 0 | 공고·RFP·양식 등 첨부파일 수집 (HWP는 PDF 변환 후 읽기) | 원본 보관 | — |
| 1 | 공고문 분석 → **사용자에게 지원 여부·대상 RFP 확인** | 공고분석.md | P1 |
| 2 | RFP 분석 (요구사항 원장 — 이후 전 항목의 기준) | RFP분석.md | P2 |
| 3 | 리서치 4종 (병렬 서브에이전트 권장) | 리서치_논문·특허·경쟁제품·연구동향.md | P3 ×4 |
| 4 | 계획서 양식에서 목차 추출·확인 | 목차.md | — |
| 5 | 목차 순서대로 집필 (각 단계 앞 산출물 전부 참조) | 1_필요성 ~ 8_사업화.md | 목차 1~8 |
| 6 | 도식화 (비교=표, 흐름=도식, 추세=그래프) | 이미지/도식 명세 | 보조[도식화] |
| 7 | 적대 검증 (별도 컨텍스트, 평가위원 관점) | 검증리포트.md | 보조[검증] |
| 8 | 최종 조립 — 양식(HWP/DOCX)에 이식, 사용자 팩트체크 요청 | 제출본 | — |

- 각 산출물의 기능·표준 구조는 [references/artifacts.md](references/artifacts.md)를 따른다.
- 프롬프트 전문은 [references/prompts.md](references/prompts.md) — 실행 시 {중괄호}를 실제 값으로 채워 사용.
- 방법론의 근거·출처 정리는 [references/sources.md](references/sources.md).
- HWP 산출이 필요하면 환경의 HWP 도구(rhwp 등)를 사용하고, 없으면 DOCX/MD로 산출 후 사용자가 이식.

## 목차가 다른 사업일 때

이 스킬의 기본 목차는 정부 R&D 표준 8항목(필요성/목표/내용·추진체계·일정/활용·기대효과/수행역량/연구개발비/안전·보안/사업화)이다. 공고의 목차가 다르면(예: PSST 4문항) 4단계에서 실제 목차를 추출해 프롬프트를 해당 항목에 매핑해 쓴다 — 원칙과 산출물 구조는 동일하게 적용.
